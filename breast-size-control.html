Introduction

Size in the text is the wrong place for size

Most attempts at this problem put the size in the prompt: large breasts, huge bust, and so on. That approach fails in three structural ways.

  1. The words leak into everything else. A caption heavy on size vocabulary drags the whole composition with it: body type, clothing fit, framing, even the subject's apparent age.
  2. The scale is not calibrated. "Large" means something different in every checkpoint and every prompt.
  3. It cannot be continuous. Text gives you a few coarse buckets, not a value you nudge.

This LoRA moves the control out of the text and into geometry. The size lives in a condition image: a black frame with one or two #FADBAE markers, where the marker's area fraction is the dial. The caption is then free to describe only the scene, and the model reads the geometry separately from the language.

The practical result is that size becomes a number you can measure and repeat, without ever typing a size word.

Calibration

Six classes, measured rather than guessed

The boundaries come from a labelled dataset: the per-class median total marker area as a fraction of the frame. Those six numbers are exactly the canvas preset buttons, so one click lands on a class the LoRA has actually seen.

Measured class mediansmarker area of frame
  • flat1.49%
  • small2.94%
  • medium3.22%
  • large7.18%
  • huge13.95%
  • gigantic16.50%

Note the shape of the ladder: small to medium is a narrow step, while medium to large to huge opens up fast. That is the measured distribution, and it is why eyeballing the size is a poor substitute for setting the area. Intermediate values are legitimate too, because the dial is continuous.

Keep the marker in-distribution

The LoRA was trained on one marker style, so three rules keep you inside it: the background stays black (no gradients, no textures, no other content); the fill stays bright, #FADBAE by default; and there are one or two ellipses whose area is the size. Overlapping markers merge as a union, not a sum, which is the behaviour the training data had.

The condition image is forced to the target's exact pixel size when you connect an image to the node. This matters, because the pipeline bucket-crops the reference and a size mismatch silently displaces the markers.

Usage

Five steps from install to sample

This LoRA must be used together with the EditUtils plugin. It will not work as intended without it.

  1. Install the pluginComfyUI-EditUtils, plus Comfyui-LoraUtils for the LoRA merge nodes used in the example.
  2. Load the LoRAbreasts_control_lrzjason_20261015.safetensors at strength 1.0, merged on top of the Krea2 turbo LoRA.
  3. Draw the controlAdd BreastSizeControl_EditUtils, drag one or two markers, and hit the preset button for the size you want. Connect a target image to force the exact output size.
  4. Write the scene prompt onlySubject, clothing, framing, light. No size words, or the text competes with the geometry.
  5. Sampleeuler / simple, 8 steps, CFG 1.0, denoise 1.0.

Notes

Things worth knowing before you run it

  • 01The caption rule is not a suggestion. If you put size words in the prompt, the text and the reference image compete for the same variable and the result drifts. Keep the text scene-only and let the geometry speak.
  • 02Higher-resolution inputs yield richer marker geometry, since the marker's edge is where the extra detail lands.
  • 03The area is the dial, not a rendering. The condition image is a control signal, not a target to be drawn literally.
  • 04Works best with long, descriptive scene captions, consistent with the dataset side, where captions were written scene-only.
  • 05Overlapping markers merge by union, so two crossing ellipses are not twice the size.
  • 06This control LoRA and the Krea2 edit path are still in development. Results depend on the LoRA checkpoint and ref_strength.
